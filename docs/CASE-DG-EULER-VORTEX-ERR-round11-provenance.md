# CASE-DG-EULER-VORTEX-ERR round 11：证据溯源闸门（C11）——把「默认假设」变成「重放证据」

锚点 `CASE-DG-EULER-VORTEX-ERR`（算例池·等熵涡移动误差守恒，ref: Yee et al. 2000，容差 <6%）。
本文件数字全部来自 `case_euler_vortex_errconserve/metrics.json`、
`case_euler_vortex_errconserve/provenance_certificates.json` 与
`artifacts/provenance_replay/`，零手抄。

## ① 为什么要有这一轮（对抗复核发现的实质缺陷）

前 10 轮把 C1–C10 建起来了，但**证据本身的可信度**只有一个判据在管：C6 只问「这个检查点有没有结果文件」。
文件存在，不代表文件里的数字属于当前这套判据：

* 结果文件 `results/*.json` 现在会写入 `reference_model`（对哪个参考解测量），
  但 32 份读数里有 **19 份写在那个字段之前**；
* 聚合器对缺失字段的处理是 `r.get("reference_model", REFERENCE_MIN_IMAGE)`，
  即**默认它是 min_image**——一个假设，不是证据；
* 而这个假设恰好在本算例的前 3 轮被打破过：早期读数是对**自由空间**公式测量的，
  涡折叠后（t > 5）自由空间公式不再是周期解，于是「误差放大 alpha≈3.3–4.4」
  是参考解缺陷，不是格式行为（见 `docs/CASE-DG-EULER-VORTEX-ERR-reference-defect.md`）。

也就是说：C2（误差守恒 alpha=0.199，设计族）与 C5（P0 交叉阶 0.849）这两条**直接支撑 <6% 验收**的判据，
其原始读数里有相当一部分**没有记录所用参考解**，只能靠「默认 min_image」站立。这是一条真实的、
可复现的过度声明（overstated claim），因此本轮新增第 11 条判据。

## ② 怎么做的

1. **新增 C11 证据溯源判据**（`benchmarks/case_euler_vortex_errconserve.py::provenance_audit`）。
   每个检查点按证据状态分类：
   * `recorded` —— 文件里记了所用参考解模型，且与本次聚合的模型一致；
   * `replayed` —— 旧文件（无记录）由 `tools/provenance_certify.py` 用**同样的配置**
     对当前参考解重放，复现原读数到 `1e-9`（相对）；
   * `unverified` —— 旧文件且无证书：**溯源未知**，判据不得判过；
   * `config_mismatch` —— 文件自带的配置与 LADDER 声明矛盾（例如声称 CFL 0.2 却写着 0.4）；
   * `missing` —— 声明了但没有文件（等价于 C6 的洞）。
2. **重放证书即数据**：`case_euler_vortex_errconserve/provenance_certificates.json`
   逐条记录 `stored_max_percent` / `replayed_max_percent` / 四场绝对偏差 /
   相对偏差 / 参考解模型 / 墙钟时间 / 容差。判据读它，不读散文。
3. **本机只跑短测试**：单条重放 ≤ 112 s 的 12 条在本机逐个跑完
   （`p0_*` 全族 + `dg_d2_n32` 的 CFL 0.4 轴与部分 CFL 0.2 轴）；
   剩余 7 条（含 44 min 的 `dg_d2_n64_t10_cfl0.2`）交给计算门 `cj3645`，
   **没落地就照实算 `unverified`**。
4. **缺的 8 个检查点**（C6/C9 的欠账：`dg_d3_n32` 全族、`dg_d1_n64` 的 t=2/5/10、`dg_d2_n32` 的 t=20）
   由计算门 `cj3626`（8 分片，跳已存在）统一补齐，本轮未落地。

## ⑤ 注意点与局限

* **重放 ≠ 独立实现**：重放用的是同一份代码、同一台机器，只换了「有没有记录参考解」这一层。
  它证明的是「旧文件与当前代码对同一检查点一致」，不能证明当前代码本身正确——
  后者由 C1–C10 的解析解对照承担。
* **超参一致性由 C11 的 `config_mismatch` 管**：文件自带配置必须与 LADDER 一致
  （任务/阶数/网格/终时/CFL/beta/方向）。本轮 32 份读数全部一致——但这是**检查后才敢说的话**，
  之前没有任何判据查过这件事。
* **未落地即未证实**：`cj3626`（8 个缺口）、`cj3645`（7 条证书）在写此报告时仍在排队
  （队列位次 37 / 48），因此 C6/C9/C11 一律记 `not_evaluated`，不用「快好了」代替判定。
* 本机纪律：单条重放在 <112 s 内完成，未与本机重计算硬拦冲突；超限的 7 条改走计算门。

## ⑥ 误差判定（是否 <3%？）

| 量 | 基准 | 误差 | <3%? |
|---|---|---|---|
| 设计族 dg_d2_n32 t=1 最大场 | 解析周期解 | 0.00943% | 是 |
| p0 n=256 t=1 最大场 | 解析周期解 | 1.519% | 是 |
| p0 n=64 t=1 最大场（C1 最差族） | 解析周期解 | 4.926% | **否**（但 <6% 容差，且它是刻意造的一阶基线） |
| 重放复现偏差（12 条最大） | 存档读数 | 1.1e-12 相对 | 是 |

结论：设计族精度远好于 3%；C1 的 4.93% 来自 LADDER 里故意保留的一阶 P0 粗网格基线，
算例池容差是 6%（Yee et al. 2000），按容差判定通过，但**不能宣称「所有族都在 3% 内」**。
