# Benchmark: systematic convergence order and GCI verification

## Problem

Every other benchmark in this repository answers "how large is the error on one
configuration". This benchmark answers a different question: **does the
implementation converge at the order the discretisation theory predicts, and is
the mesh-converged limit consistent with the analytic solution?**

Targets:

| problem | method | degrees | theoretical L2 order | refinement |
|---|---|---|---:|---|
| 2D Poisson, manufactured `sin(pi x) sin(pi y)` | SIPG | P1, P2, P3 | 2, 3, 4 | h |
| 1D periodic linear advection, `sin(2 pi x)` | Legendre DG, upwind, RK4 | P1, P2 | 2, 3 | h |
| 1D heat, `sin(pi x) exp(-pi^2 t)` | SIPG + Crank--Nicolson | P1, P2 | 2, 3 (fixed dt) | h |
| 1D heat, domain mean | Crank--Nicolson | P2 | 2 | dt |
| 2D Poisson, matrix-free PCG backend | SIPG | P1 | 2 | h |
| all smooth problems on a fixed mesh | DG p-enrichment | 0--3 | superlinear (spectral) | p |

## Method

- `tensordg/convergence.py` provides the estimators: least-squares observed
  order, pairwise orders, Richardson extrapolation, Roache's three-grid order
  with GCI (safety factor 1.25), and p-refinement decay diagnostics. It also
  extracts scalar quantities of interest (point values, domain mean, L2 norm)
  from modal DG coefficients.
- Acceptance criteria: `|p_obs - p_theory| <= 0.2`; `GCI(fine) >= true error`
  against the analytic solution; asymptotic ratio in `[0.8, 1.25]`;
  p-refinement monotone and superlinear.
- Reference policy: analytic manufactured solutions plus Richardson/GCI
  extrapolation only. No reference value is generated by the implementation
  under test.

## Run

```bash
python -m pip install -e ".[dev]"
python -m benchmarks.convergence_study
# or with an explicit output directory (default shown)
python -m benchmarks.convergence_study --output docs/benchmarks/results/convergence
pytest -q tests/test_verification.py
```

| `summary.md` | Markdown tables rendered from `metrics.json` (no hand transcription) |

## Known limitation (reported, not hidden)

For the heat equation the time step is held fixed while the mesh is refined, so
the total error has a Crank--Nicolson floor that h-refinement cannot remove; the
h-based GCI therefore estimates only the spatial part of the error and
underestimates the total. The driver marks that single check
`NOT_APPLICABLE` with the reason attached and quantifies the floor with a
separate dt-refinement study (second-order temporal convergence). See the
tutorial for the full discussion.
