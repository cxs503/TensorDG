# CASE-REPRO-DG-CKS1998 · DG P2 Sod 门：已公布 2.368 % 在当前代码上不复现

> 锚点：`REPRO-DG-CKS1998`（论文复现·Cockburn & Shu 1998, JCP 141:199-224）
> 性质：**验证欠账结算（falsification）**——把上一轮 `docs/CASE-REPRO-DG-CKS1998-DUAL-INSTRUMENT-GATES.md`
> §3.3「已公布 2.368 % vs 缓存剖面 3.8384 %」这条**挂账未解**的分歧，用**第三个独立读数**判掉一半，
> 并给出另一半的可执行证伪配方。不改求解器、不改容差、不改台账判决。

## ① 案例介绍

CKS1998 §5 的 E2 算例：Sod 激波管（Toro test 1），γ=1.4，左态 (ρ,u,p)=(1,0,1)、右态 (0.125,0,0.1)，
膜片 x=0.5，域 [0,1]，**t=0.2**。判据：DG **P2**、**N=400**（该阶最细网格）上的**最差场量相对 L2 < 3 %**。

| 配置项 | 取值 | 出处 |
|---|---|---|
| 格式 | DG P2 + TVB 限幅（M=1，`limiter_stage="final"`） | `validation/repro_cks1998/repro_cks1998.py::run_sod` |
| CFL / 步数 | 0.12 / 7281（N=400） | 同上 |
| 正性保护 | Zhang-Shu 缩放（`positivity="scale"`，默认） | `tensordg/euler_dg_1d.py` |
| 参考解 | 断点切分精确单元平均（第二台仪器：固定 8 点 Gauss） | `validation/repro_cks1998/station_reference.py` |

**要判的问题只有一句**：仓库公布的 `p2_n400` 最差相对 L2 = **2.368 %（PASS）** 到底是当前代码的读数，
还是一份旧代码状态的读数？若是后者，则锚点的 E2 头号 PASS 结论**在当前代码上不成立**。

## ② 怎么做的

1. **钉死两端数字的出处**：公布值 2.368 % 来自 `docs/CKS1998-round2-results.md`（quick 与 full 两档一致）
   与 `docs/AUDIT_m15345_REPRO-DG-CKS1998.md`；缓存剖面 `sod-dg-p2-n400.npz`
   （sha256 `eb8c0ee1…`，集群作业 `cj3966` 产出）在同一配置下读 3.8384 %（旧仪器）/3.7702 %（精确仪器）。
   两者的指纹差 1.4704 pp，而**仪器位移 ≤0.07 pp**（上一轮实测）⇒ 不是仪器问题。
2. **代码状态取证**：`git log` 查 `tensordg/euler_dg_1d.py`、`tensordg/euler_1d.py`、`tensordg/limiters.py`
   在公布日（11-13）之后的全部改动，逐条读 diff——11-13/11-14 的三次改动（`m18266`、`m18517`）
   **只增 `dt`/`dt_last`/`dt_mean` 元数据，数值路径零改动**。⇒ 公布值与缓存值的差**不能**用"这两天的提交"解释。
3. **第三个独立读数（本单新增）**：新增
   `validation/repro_cks1998/sod_p2_gate_recompute.py`——**不复用缓存**，按文档配置从零重跑并同时对两台仪器打分；
   预登记一个扫描（`limiter_stage`/`positivity`/`tvb_constant`/`cfl`/`degree`，即门行未钉死的全部隐式轴）
   用来区分"配置错配"与"代码状态错配"。
4. **可负担的判决实验**：N=400 一次跑 ~110 s 超出本机短测预算，故先做 **N=200 档**（同阶同配置，3628 步、
   52.6 s，实测耗时）——公布表里 N=200 也有公布值 **4.173 %**，于是"当前代码 vs 公布流水线"在**两个网格**
   上都有对照。N=400 全扫描递交集群（`cj4713`，`cores=2`，`stage_dir=本工作树`）。

## ③ 计算结果（全部程序化注入，零手抄）

### 3.1 同一配置、三个读数（N=400，最差场量 = 速度）

| 来源 | 速度相对 L2（旧仪器） | 精确仪器 | 相对公布值 | 判决（3 %） |
|---|---:|---:|---:|:--:|
| 已公布（round2 quick/full、AUDIT_m15345） | **2.368 %** | —（当时未测） | — | PASS |
| 缓存剖面 cj3966（sha256 `eb8c0ee1…`） | **3.8384 %** | 3.7702 % | +1.4704 pp | **FAIL**（−0.77 pp） |
| 本单 N=400 从零重跑 | **not_run**（`cj4713` 排队 10.3 min 仍未起跑） | — | — | 未判定 |

### 3.2 N=200 档的对照（本单实测，闭区间上可负担的那一档）

| 项 | 已公布（round2） | 本单实测（当前代码 `2901cff8`） | 比值 |
|---|---:|---:|---:|
| 最差场量（速度）相对 L2 | **4.173 %** | **6.1256 %**（旧仪器）/ **5.7929 %**（精确仪器） | 1.468 |
| 密度相对 L2 | —（未逐场公布） | 1.6916 % / 1.6455 % | — |
| 压力相对 L2 | —（未逐场公布） | 1.4564 % / 1.4077 % | — |
| 仪器位移（旧−精确） | — | **0.3327 pp**（速度） | — |
| 步数 / 墙钟 | — | 3628 步 / 52.6 s | — |

对照 N=400（缓存 vs 公布）比值 **1.621**，N=200（实测 vs 公布）比值 **1.468**：**两个网格同向偏大、量级相同**。

### 3.3 判读

- **同向、跨网格**的偏大不能由"某一档配置笔误"解释：配置错配会挑一个网格，代码状态错配会同时挑两个。
  因此本单把 §3.3 的挂账判定为 **代码状态错配（公布的 2.368 % 是旧读数）**，而不是仪器或配置问题。
- **判决确实翻转**：门判的是 P2 最细网格 N=400；缓存剖面在**两台仪器下**都越界（3.8384 / 3.7702 > 3 %，
  裕度 **−0.77 pp**）。所以 **「E2 · P2 N=400 < 3 % PASS」在当前代码上不成立**——这是 honest FAIL，
  本单**不**通过放宽容差、改门例网格或改仪器来"修回 PASS"。
- N=200 档的判决（FAIL）**没有翻转**（公布 4.173 % 也 FAIL），翻转只发生在 N=400 这一档上——
  与"漂移量 ~1.5 pp 而 N=400 的公布裕度只有 0.63 pp"这一算术一致。

## ⑤ 注意点 / 局限（honest）

1. **N=400 从零重跑未完成（not_run）**：`cj4713`（文档配置 + 7 条预登记扫描，`cores=2`）递交后排队
   10.3 min 仍在 `queued`（队列 123 位），本单**没有** N=400 的第三读数。已有的 N=400 证据是
   `cj3966` 的缓存剖面（本单核对了它的 meta 与文档配置逐项一致：degree 2 / N=400 / CFL 0.12 /
   limiter tvb / stage final / positivity scale / 7281 步）。补齐命令：
   `OMP_NUM_THREADS=1 PYTHONPATH=. python3 -m validation.repro_cks1998.sod_p2_gate_recompute --out docs/benchmarks/results/cks1998_dual_instrument/sod_p2_gate_recompute.json`；
   回执 JSON 含 `configs_reproducing_published` 与 `attribution` 两个字段，若某条邻居配置复现了 2.368 %
   则归因改为"配置错配"——**这两个字段由程序判定，不由作者叙述**（`tests/test_sod_p2_gate_recompute.py` 钉死）。
2. **没有定位到具体提交**：11-13 之后 `euler_dg_1d.py`/`euler_1d.py`/`limiters.py` 的三次改动已逐条读
   diff、确认数值惰性；漂移必然来自更早的提交。可执行证伪：对 `2901cff8` 之前、`5ee54fdc`（round2 文档
   合并）之后的提交做 `git bisect run`，判据用 N=200 档（52.6 s/次，可负担）的速度相对 L2 是否越过 4.173 %。
   本单不猜提交号。
3. **N=200 档的公布值只有最差场量**：公布表未逐场列出 N=200 的 ρ/p，故 3.2 表中"密度/压力"两行的
   已公布栏留空（不补造数字）。
4. **仪器位移随网格变化**：N=200 为 0.333 pp、N=400 为 0.068 pp，说明"仪器位移 ≤0.07 pp"这条
   结论**只在 N=400 上实测过**，不能外推成网格无关的上界；本单如实缩小该论断的适用范围。
5. **本单不改台账**：`feature_ledger` 的锚点状态、3 % 容差、`GATE_EXPECTATIONS` 的 2.368 % 指纹
   **一律未动**。指纹档 `mismatch` 正是它该有的状态（它记的是"公布值"，本单证明公布值本身是旧读数）。
   建议由派发器决定是否把锚点 E2 的公布结论改写为"当前代码 FAIL −0.77 pp"。
6. **适用范围**：本单只判 E2 的 P2 支路；P0/P1 支路（1-D N=3200 速度 2.4602 %、P1 N=400 2.346 %）
   的指纹在上一轮已 **match**（差 −0.0000 pp），漂移不涉及它们。

## ⑥ 误差判定（逐项回答「是否 < 3 %」）

| 关键量 | 基准 | 读数 | 是否 < 3 % |
|---|---|---:|---|
| P2 N=200 速度相对 L2（当前代码） | 精确 Riemann 单元平均 | **5.7929 %** | **否**（越界 2.79 pp） |
| P2 N=200 速度相对 L2（旧仪器） | 固定 8 点 Gauss 单元平均 | **6.1256 %** | **否** |
| P2 N=200 密度/压力（精确仪器） | 精确 Riemann 单元平均 | 1.6455 % / 1.4077 % | 是 |
| P2 N=400 速度相对 L2（缓存剖面，当前代码状态） | 精确 Riemann 单元平均 | **3.7702 %** | **否**（越界 0.7702 pp） |
| P2 N=400 速度相对 L2（公布值） | 同上 | 2.368 % | 是——但**不复现**，见 ③ |
| N=200 档"实测 ÷ 公布" | 1.468 | — | 否（漂移 46.8 %，**不是**舍入或仪器） |
| N=400 档"缓存 ÷ 公布" | 1.621 | — | 否（漂移 62.1 %） |

**一句话**：在能实测的那一档（N=200）上，当前代码比公布值**大 46.8 %**，把 3 % 门越界 2.79 pp；
在缓存剖面给出的 N=400 档上越界 0.7702 pp。**「E2 · P2 N=400 < 3 %」在当前代码上不成立**，
2.368 % 是旧代码状态的读数。本单不粉饰这一条，也没有把任何容差改宽。
