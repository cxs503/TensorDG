## 1. 案例介绍

### 1.1 为什么这是缺口（验证欠账）

`euler_dg_2d` 是 2D 可压缩栈的主力（限制器、熵预算、Sod 挤出、等熵涡都跑在它上面），但
`validation/euler_dg_2d/evidence.json` 里 `vortex` 只记录了 **degree=2、cells 16 与 24 两档**，
EOC 2.9476/2.9729。单区间证据无法区分四种情况：真设计阶、超收敛、前渐近窗口、以及
初始投影把高阶模态清零导致的阶数封顶（后者正是 m2143 修掉的历史缺陷）。本单把这条欠账补成
**阶数 × 网格的二维矩阵**，并且判据先于实验。

### 1.2 物理与精确解

二维可压缩 Euler（γ=1.4，单位气体常数），周期盒 `[-5,5]²` 上的**等熵涡**（Klein 涡）：

    u = 1 - β y/(2π) exp((1-r²)/2),   v = 1 + β x/(2π) exp((1-r²)/2)
    T = 1 - (γ-1) β²/(8 γ π²) exp(1-r²),   ρ = T^{1/(γ-1)},   p = ρ T

β = 5，r² = x²+y²（随背景平流 (1,1) 平移）。它是 Euler 方程的**精确解**（无制造源项），
因此误差可以逐点对解析式度量，是最干净的阶数验证基准。

### 1.3 参数表（判据全部可机器裁）

| 项 | 设定 |
|---|---|
| 域 / 边界 | `[-5,5]²`，双周期 |
| 精确解 | 等熵涡 β=5，背景 (1,1)，终时 t=1.0 |
| 时间推进 | SSP-RK3，CFL=0.2（与生产默认一致） |
| 初始投影 | `l2`（模态 L2 投影，非 P0 常值） |
| 网格阶梯 | P1 (12,16,24,32)²；P2 (8,12,16,24)²；P3 (6,8,12,16)² |
| 误差度量 | 体求积节点上 `(ρ,u,v,p)` 相对 L2，求积阶 max(p+2,3) |
| 判据 1 | 最小二乘拟合斜率 vs 设计阶 p+1 的相对偏差 ≤ 3% |
| 判据 2 | 最细网格四场相对 L2 < 3%（工程门） |

## 4. 误差判定（逐项，显式回答「是否 < 3%」）

| 关键量 | 基准 | 实测 | 相对偏差 | < 3%？ |
|---|---|---:|---:|---|
| P1 总体阶（ρ 拟合） | 2（设计阶 p+1） | 2.04 | +2.0% | **是** |
| P1 总体阶（u/v/p 拟合） | 2 | 2.01 / 1.98 / 2.00 | +0.5% / −1.0% / 0.0% | **是** |
| P2 总体阶（ρ / p） | 3 | 3.00 / 2.93 | 0.0% / −2.3% | **是** |
| P2 总体阶（u / v） | 3 | 2.86 / 2.84 | −4.7% / −5.3% | **否** |
| P3 总体阶（ρ / p） | 4 | 3.85 / 3.85 | −3.75% / −3.75% | **否（差 0.75 个百分点）** |
| P3 总体阶（u / v） | 4 | 3.52 / 3.48 | −12.0% / −13.0% | **否** |
| P1 32² 精度（最差场 u） | 解析涡 | 2.0115e-03 | 0.20% | **是** |
| P2 24² 精度（最差场 v） | 解析涡 | 2.4326e-04 | 0.024% | **是** |
| P3 16² 精度（最差场 v） | 解析涡 | 1.1623e-04 | 0.012% | **是** |

**结论（诚实口径）**：好消息是**精度门全过**（最细网格全部 ≤ 0.20%，远小于 3%），
**P1 达设计阶、P2 的密度/压力通道达设计阶**；**未达标项**：P2 的速度通道低 5%、
**P3 全通道低于设计阶 3.8%–13%**。这不是「数值实现错了」（P3 的 EOC 随网格加密单调上升、
最后一个区间压力通道已达 4.10），更像**前渐近 + 时间推进阶数（SSP-RK3 只有 3 阶）**的组合
效应：P3 的空间阶 4 需要更细的网格才能把 O(dt³)=O(h³) 的时间误差压下去。见 §5 局限。

## 5. 注意点（踩坑 / 局限 / 适用范围）

1. **单区间证据会骗人**：本仓库原有的 P2「EOC 2.95」恰好落在 16²→24² 区间的局部值上，
   而 P2 的 8²→12² 区间只有 2.66（速度通道）——只用首末两档拟合会高估。本单改为
   **逐区间 EOC + 全档最小二乘**双口径，两者都写进 JSON。
2. **P3 需要更细网格**：6²–16² 对 p=3 是明显的粗网格区（h 1.67→0.63），只能给出**阶数下界**；
   要拿到 4.0±3% 需要 top mesh ≥ 24²–32²（估计墙钟 ×4，本机当时 load15 已 200+，未做）。
   **这是本单未完成的部分，如实标注**。
3. **时间推进共同限速**：SSP-RK3 的时间阶 3 < P3 的空间阶 4，阶数验证必须让 dt 比空间尺度更快
   收敛（本单靠 CFL 让 dt∝h，仍可能污染最后一位）；严谨做法是固定 dt 做「空间-only」扫描，
   或换 RK4。未做。
4. **共享机负载纪律**：跑批时 load1 一度 800–1000（128 核里其他席占满）。本单全部
   `OMP_NUM_THREADS=1` 单进程 + 小网格（最大 32² P1 / 24² P2 / 16² P3，DOF ≤ 2.1e4），
   合计 134.5 s；**集群节点（n315/n330，load≈35）因未装 torch 不可用**，已核实
   （`ModuleNotFoundError: No module named 'torch'`），故留本机单线程。
5. **`metadata["dt"]` 不是平均步长**：12² 报 6.706e-03、16² 报 7.267e-05，步数却是 106→142
   （即平均 dt 必然 ∝h）。该字段是「最后一步的 dt」，做时间阶分析时不能用它，须用
   `final_time/steps`。本报告未使用该字段。
6. **一次徒劳的旁支（记录以免后人重复）**：本单开工时先想去修 m2589 报告的「壁面瞬态
   t≈0.0328 失稳（增长率 ∝ σ）」这条 open defect，用**仓库自带的 `tools/diag_ns_wall.py`
   同款 march**（2×8 P1、σ=2）从静止态与解析稳态分别推进 300/400 步，**均未复现失稳**
   （`tools/probe_wall_sign.py`，含通道/符号扫描）。结论：summary.json 与已发布 march 代码
   存在**口径不一致**（该 march 起始态是解析稳态 Couette，而报告文字写「从静止起动」），
   在没拿到生成 JSON 的原始代码前不下结论、也不改 `ns_dg_2d.py`。这条留给后续单。
7. 适用范围：验证的是**光滑解**（无激波）；带限制器的激波算例阶数另论（见
   `docs/limiter_2d_verification.md`）。`initial_projection="l2"` 是前提；改回 P0 初始会把阶封顶（m2143）。
