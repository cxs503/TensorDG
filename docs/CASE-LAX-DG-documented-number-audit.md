# CASE-LAX-DG · 文档里那个「2.769420 %」到底是什么

> 锚点：`feature_ledger` `CASE-LAX-DG`（验收原文「ref: 精确解｜容差 < 3 %」，status `open`）。
> 工件：`docs/benchmarks/results/lax_documented_number_audit/metrics.json`（本文数字全部由
> `benchmarks/lax_documented_number_audit.py` 程序化注入，零手抄；`--check` 在漂移时失败）。
> 生成时刻 2026-11-15T05:41:17Z。

## ① 案例介绍

Lax (1954) 激波管 / Toro (2009) Test 2：`[0,1]` 域、隔膜 `x0 = 0.5`、γ = 1.4、
快照 `t = 0.13`。左态 (ρ, u, p) = (0.445, 0.698, 3.528)，右态 (0.5, 0, 0.571)。
闭式星区 `p* = 2.466098`、`u* = 1.528723`；四道波的位置闭式给出
（稀疏头 `0.157637`、稀疏尾 `0.287229`、
接触 `0.698734`、激波 `0.822312`），接触与激波是**真跳变**。

仓库对这条算例的公开口径是「P3 DG + HLLC + 局部保正回退，400 单元，
对精确 Riemann 解 **max 2.769420 %**」，出现在 `README.md`、`docs/tutorials/nonlinear-dg-benchmarks.md`、
`expand_audit_tensordg.md`，并被 `docs/reports/tensordg-gate-power-audit.md` 当作「3 % 门余量 1.08」的证据。
本单只问三件事：这个数**今天还复现得出来吗**？它是解的性质还是**求积尺**的产物？**去掉尺**之后判决是什么？

## ② 怎么做的

1. **跑一次登记构型**：`p3.N400`，CFL = 0.35，t = 0.13，当前 main 的
   `solve_euler_dg_1d`（模态 DG + HLLC + SSP-RK3 + Zhang-Shu 保正缩放），步数 5109。
2. **Q1 溯源**：用文档声明的度量模块 `benchmarks.riemann_dg_error.riemann_dg_errors`（默认 8 点 Gauss 规则）
   与同一模块扫 `q ∈ [4, 5, 6, 8, 10, 12, 16, 20, 24, 32]`，看是否有任何读数落在 2.769420 % 的 1e-4 内；
   再用 `git archive 432bef057` 把**首次发布这个数的那个提交**的求解器取出来
   在子进程里重跑同一构型（只读、不切分支），把「2.769420 % 是谁算的」钉死。
3. **Q2 尺**：写一个**独立于** `benchmarks.lax_case_pool` 与 `benchmarks.lax_a0_quadrature_audit` 的
   波对齐评估器——每个单元按解析断点切成光滑子段，子段上用 `q = [40, 160, 640]` 点 Gauss 积分
   DG 多项式与精确解，子段数加密到收敛；断点位置同时用闭式（等熵 + Rankine-Hugoniot）与
   细网格探测两种方式给出，作为灵敏度检查。
4. **Q3 判决**：收敛读数对台账容差 `0.03`（取自 `tensordg.cases.lax_1d.lax_parameters()`，
   未手抄）逐量比较；并与已提交的正交审计工件交叉核对（两个独立实现的收敛读数应一致）。

## ③ 计算结果

### 3.1 固定解、只动求积规则（文档声明的度量模块）

| Gauss 阶 q | ρ rel L2 | u rel L2 | p rel L2 | 三量最差 vs 3.0 % |
|---:|---:|---:|---:|---|
| 4 | 3.3025 % | 2.6030 % | 1.4705 % | FAIL |
| 5 | 3.3480 % | 2.2841 % | 1.3059 % | FAIL |
| 6 | 2.9696 % | 2.1058 % | 1.2353 % | PASS |
| 8 | 2.9058 % | 1.9365 % | 1.1905 % | PASS |
| 10 | 3.1156 % | 2.2481 % | 1.3050 % | FAIL |
| 12 | 3.0050 % | 2.0771 % | 1.2359 % | FAIL |
| 16 | 3.0700 % | 2.1633 % | 1.2710 % | FAIL |
| 20 | 2.9690 % | 1.9947 % | 1.2116 % | PASS |
| 24 | 3.0060 % | 2.0559 % | 1.2313 % | FAIL |
| 32 | 2.9806 % | 2.0083 % | 1.2164 % | PASS |

默认 `q = 8` 的读数是 **2.9058 %**（density），
判定 **PASS**；规则从 4 扫到 32，密度读数在
**2.9058 % – 3.3480 %**
之间摆动（跨度 0.442 个百分点），判决在 PASS/FAIL 之间**翻来覆去**。

### 3.2 波对齐（去尺）读数

| 子段点数 | ρ | u | p |
|---:|---:|---:|---:|
| 40 | 3.025074 % | 2.073699 % | 1.238454 % |
| 160 | 3.025074 % | 2.073699 % | 1.238454 % |
| 640 | 3.025074 % | 2.073699 % | 1.238454 % |

收敛读数取最细一档：**ρ = 3.0251 %**、u = 2.0737 %、
p = 1.2385 %；最差量 `density`，
对 3.0 % 的判定为 **FAIL**。
断点用细网格探测替代闭式位置时读数不变（`detected_breaks_640` 与最细一档差 < 1e-3 个百分点），
说明收敛读数不依赖断点检测方式。交叉核对：已提交工件的收敛读数 = 3.0251 %，本驱动独立实现读数 3.0251 %，偏差 0.00000 个百分点。

### 3.3 溯源：2.769420 % 是谁算的

| 来源提交 `432bef057` 的求解器，度量同 `riemann_dg_error` | ρ | u | p |
|---|---:|---:|---:|
| q = 8 | 2.7694 % | 1.6053 % | 0.9194 % |
| q = 10 | 2.9537 % | 1.9551 % | 1.0433 % |

该提交（2026-10-23，首次发布 README 表与 `benchmarks/riemann_dg_error.py`）的求解器在默认 `q = 8` 下
逐位复现 **2.769420 % / 1.6053 % / 0.9194 %**——与仓库公布的三个数完全一致；当前 main 的求解器
在同一构型、同一规则下读数是 **2.9058 %**。也就是说，公布的数
**绑在 2026-10-23 的求解器版本上**，之后求解器演化（限幅/保正/通量路径）改变了离散解，
而文档表格没有跟着更新：当前度量族里离它最近的读数是 `q = 8`
的 2.9058 %，
相差 0.1364 个百分点
（`documented_reproducible_from_main = False`）。

## ⑤ 注意点

1. **本单不改台账口径**：`CASE-LAX-DG` 钉扎腿仍是 `p3.N400`，其诚实 FAIL（池子 10 点规则读数
   3.1156 %）原样保留；本文只是把「文档口径 PASS」这件事查清楚——它的 PASS 来自**尺**与**旧求解器**，
   不是来自解本身。
2. **求积规则不是自由旋钮**：精确解在单元内有四个解析断点，固定 Gauss 规则在这些点上不可积全，
   `q = 8` 与 `q = 10` 的密度读数差 0.21 个百分点，足以跨过 3 % 门。任何用固定规则对 3 % 级容差
   下判决的地方（不止本算例）都应先做这一步对齐检查。
3. **保正回退是当前读数的原因之一**：两个求解器版本的差别（含 Zhang-Shu 缩放与 HLLC 路径）本身
   就足以让 ρ 从 2.7694 % 走到 2.9058 %（`q = 8`），因此「旧数 + 新码」的组合在任何规则下都不成立。
4. **收敛读数的不确定度可量**：子段 40/160/640 三档给出 3.025074 % /
   3.025074 % / 3.025074 %，跨度仅
   2.26e-14 个百分点
   （子段已在解析断点处切开，被积函数光滑），远小于它对 3 % 门的 0.025 个百分点裕度，判决不受影响。
5. **适用范围**：结论只对登记构型（p3、N=400、CFL 0.35）与这套精确解成立；换网格/换阶须重跑本驱动。

## ⑥ 误差判定（逐项回答「是否 < 3 %」）

| 判据 | 量 | 值 | 基准 | 是否 < 3 % |
|---|---|---:|---:|---|
| 文档公布（README/tutorial/expand audit） | ρ rel L2 | 2.7694 % | 3.0 % | 是（但**不可复现**：绑在 432bef057 的求解器上） |
| 当前求解器 + 默认规则 q = 8 | ρ rel L2 | 2.9058 % | 3.0 % | 是（依赖规则） |
| 当前求解器 + 池子规则 q = 10 | ρ rel L2 | 3.1156 % | 3.0 % | 否 |
| 去尺（波对齐收敛） | ρ rel L2 | 3.0251 % | 3.0 % | **否** |

**结论**：文档里的 2.769420 % 是 2026-10-23 那个求解器的读数，当前 main 在文档声明的度量下
读数不同（2.9058 %）；更重要的是删掉固定求积规则这一层后，同一离散解对精确解的
密度相对 L2 是 **3.0251 % > 3.0000 %**，即
**不满足** < 3 %。文档表格与门审计里的该条据此更正。
