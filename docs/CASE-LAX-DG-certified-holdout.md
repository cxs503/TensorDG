# CASE-LAX-DG · 认证前沿能不能外推？—— 用没参与拟合的腿去检验

> 锚点 `CASE-LAX-DG`（`ref: exact solution | tolerance < 3 %`，status `open`）。生成时间 `2026-11-15T13:43:30Z`；容差从 `tensordg.cases.lax_1d` 导入 = `0.030000`。
> 上游：`docs/benchmarks/results/lax_certified_configuration/metrics.json`（8 条枚举腿，认证 `p2.N800`）、
> `docs/benchmarks/results/lax_resolution_closure/metrics.json`（p3 阶梯 200/400/800/1600）。

## ① 案例介绍

Lax (1954) / Toro test 2 激波管：`[0,1]`、`x0 = 0.5`、γ = 1.4、t = 0.13；左态 `(ρ,u,p)=(0.445,0.698,3.528)`，
右态 `(0.5,0,0.571)`；闭式星区 `p* = 2.466098`、`u* = 1.528723`。四道波：左稀疏头/尾、接触间断、右激波，
后两者是真跳变，因此全场相对 L2 的收敛率被压到约 `h^0.4`，而不是 DG 的光滑阶。

判据沿用台账原文：10 点 Legendre–Gauss 逐点对闭式 Riemann 解、全场相对 L2、**取最差场量**，
与 3 % 比较，无场量豁免、无去波带、无平均。

**本单要回答的不是「算得准不准」，而是「认证那句话能推多远」**：枚举研究把认证收在网格内
（原话：「every measured leg with strictly smaller DOF than the certified one FAILs. No claim is made about
unmeasured (p, N)」）。一个要给用户推荐配置的算例池，必须知道这条边界是离散化的性质，还是枚举的巧合。

## ② 怎么做的

两条腿，两条路径，一起做：

**(A) 回顾性 out-of-sample（本文件有数字）** —— 分辨率闭合阶梯里的 `p3.N200`（DOF 800）与
`p3.N1600`（DOF 6400）**从未进入枚举网格、也从未参与本线任何拟合**。用 8 条枚举腿拟合两个误差模型，
用同一套 LOO 窗口判它们的预测：

* `dof`：`log e = a + b log((p+1)N)`（单一 DOF 幂律）；
* `family`：每阶一条 `log e = b_p log N`（阶数内插）。

`p3.N1600` 的 DOF 6400 **超出枚举网格的拟合区间 (800…3200)**，所以这条腿同时是外插检验。
诚实标注：这两个测试点是**先存在、后拟合**的，不是我预登记的盲测点（选择不盲），
因此它是比预登记弱一档的证据，不能被读成「前沿已经证明」。

**(B) 预登记盲测（结构性保证，测量待集群）** —— `predictions.json` 在**任何新求解之前**写下了两条
未测量腿的预测：`p2.N600`（DOF 1800，比认证腿小）与 `p3.N600`（DOF 2400 = 认证腿同 DOF），
预测器只许用枚举腿拟合，窗口取模型自身 LOO 最大残差，两模型一致才给共识判定。
两阶段 CLI（`--predict` 写预登记 → `--run` 才求解）使「先预测后测量」成为结构约束而非承诺。

**度量与求解一行都没有重写**：hold-out 的求解与度量 import 自 `benchmarks.lax_case_pool.run_ladder`
（P3 HLLC + 正定性回退、SSP-RK3、CFL 0.35、10 点 Gauss），容差从注册算例导入；
测试 `tests/test_lax_certified_holdout.py` 用 AST 断言驱动**没有** import 求解器核，防止度量口径漂移。

## ⑤ 注意点（坑 / 局限 / 适用范围）

1. **回顾性外样本 ≠ 预登记盲测**。p3.N200 / p3.N1600 是先存在后拟合的测量，
   选择不盲，只能说明「模型没被这两点打破」，不能说明前沿处处成立。
2. **窗口是模型自校准尺度，不是置信区间**。LOO 最大残差只给量级；超窗的正确读法是
   「模型外推不足」，不是「求解器错了」。
3. **`(p+1)N` 揉掉了 CFL 效应**：三阶 RK 的稳定步长随 p 收紧，`dof` 模型把 p 折算成 DOF 时忽略这一点，
   所以按阶数分别拟合的 `family` 在物理上更对；两者并列正是为了让这个分歧可见。
4. **本单不改台账**：生产腿 `p3.N400` 的 3.116 % honest FAIL 仍在账上；本单一个字都没改求解器。
5. **本机算力纪律**：单腿 600 单元在 128 核共享机上实测超过 120 s 短测试上限，故走集群递交；
   机器忙时排队数十分钟，这是「测量未到账」的真实原因，不是遗漏。

## ⑥ 误差判定（是否 < 3 %）

| 关键量 | 基准 | 数值 | < 3 %？ |
|---|---|---|---|
| `p3.N200` 最差场量（实测） | 闭式 Riemann 精确解 | 4.200 % | 否（honest FAIL） |
| `p3.N1600` 最差场量（实测） | 闭式 Riemann 精确解 | 1.875 % | 是 |
| 外样本预测偏差（`family`，最坏） | 模型自身 LOO 窗口 | 0.432 % | 是（在窗口内） |
| 台账生产腿 `p3.N400` 密度 L2（未改） | 闭式 Riemann 精确解 | 3.116 % | 否（honest FAIL 仍在账） |

**结论（限定范围内）**：在 `p3` 阶数上，用枚举腿拟合的误差模型对**未参与拟合**的 `N=200`（向外小步）与
`N=1600`（DOF 6400，**超出拟合区间**）两条腿的重建偏差最大 0.432 %，
全部落在模型自身 LOO 窗口内，PASS/FAIL 判定全部复现；因此「枚举网格上的认证前沿」在这两条腿上
**没有被打破**。但盲测腿（`p2.N600` / `p3.N600`）的测量尚未到账，
所以**不能**据此宣称前沿可外推——那是预登记实验要回答的问题。
