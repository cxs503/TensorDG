# CASE-LAX-DG · 已提交工件的可复现带（跨栈漂移的量化与闸门归属）

> 锚点 `CASE-LAX-DG`（`feature_ledger` status=open，验收原文「ref: 精确解｜容差 < 3 %」）。
> 上游：`docs/CASE-LAX-DG-artifact-staleness-audit.md`（把工件间的漂移归因为**线程数**，
> 并把「线程数写入 `environment`」列为后续项）；`docs/CASE-LAX-DG-residual-gap.md`。
> 本文把那个归因**证伪**，并把真正可测的量——**跨栈可复现带**——量化、入册、加闸门。
> 全部数字由 `benchmarks/lax_reproducibility_band.py` 与
> `docs/benchmarks/results/lax_reproducibility_band/metrics.json` 程序化注入，零手抄。

## ① 案例介绍

Lax (1954) / Toro (2009) test 2 激波管：`[0,1]`，隔膜 `x0 = 0.5`，γ = 1.4，
左态 `(ρ,u,p) = (0.445, 0.698, 3.528)`，右态 `(0.5, 0.0, 0.571)`，快照 `t = 0.13`。
精确解为左稀疏波（head/tail）、接触间断、右激波的四波闭式 Riemann 解，参考值不依赖任何数值解。

台账臂（`feature_ledger` 的验收读数）是 `p3.N400` 的**全场相对 L2 密度**
= `3.1155618811580767e-02`（3.116 % > 3 %，honest FAIL，本单不动）。

## ② 怎么做的

**问题**：仓里所有 CASE-LAX-DG 工件都以最后一位有效数字对外引用，但「工件可复现」
此前只用**两个已提交文件互比**（`test_shared_legs_agree_with_the_committed_pool`，
容差 `REUSE_TOL = 1e-6`）来论证。已提交文件不会重跑，所以这种闸门**在换机器时永远不可能响**。

**本单的三步**：

1. **实测重跑**：用同一份代码在本机（`torch 2.7.1` / `numpy 2.4.6`）重跑 `p3.N100/N200/N400`，
   与工件（`torch 2.13.0` / `numpy 2.0.1`，loongarch64 节点）逐位比较。
2. **分离两种候选成因**（上游审计没能分离）：
   * **线程数**：每条腿分别在 `torch.set_num_threads(1)` 与 `(8)` 下测量，场数组**逐位**比较
     （sha256）；
   * **栈**：用新模块 `tensordg.reproducibility.environment_fingerprint()`
     把 `python/numpy/torch` 版本、机器、CPU 型号、线程数写入工件。
3. **闸门归属**：新增 `tests/test_lax_reproducibility_band.py`（12 条），把三条结论变成不变量：
   同栈逐位复现、跨栈漂移随步数单调、台账度量（L2）跨栈稳定而 L1 不稳定。

## ③ 计算结果

### 3.1 两条栈

| 工件 | python | numpy | torch | machine / CPU | `environment` 块 |
|---|---|---|---|---|---|
| `lax_asymptotic_probe`（已提交） | 3.11.6 | 2.0.1 | **2.13.0** | loongarch64 | 有（缺 `cpu`/`torch_threads`） |
| `lax_case_pool`（已提交） | — | — | — | — | **`null`（provenance 缺失）** |
| 本单重跑（本机） | 3.11.6 | **2.4.6** | **2.7.1** | loongarch64 / Loongson-3C6000/D | 有（完整指纹） |

### 3.2 跨栈漂移（本机重跑 vs 已提交工件，全场相对 L1 密度）

| 腿 | 步数 | 已提交 | 本机重跑 | 相对漂移 | 步数一致 |
|---|---|---|---|---|---|
| `p3.N100` | 1271 | `1.5847005257e-02` | `1.5847006858e-02` | `1.010e-07` | 是 |
| `p3.N200` | 2547 | `1.2147420336e-02` | `1.2147470115e-02` | `4.098e-06` | 是 |
| `p3.N400` | 5109 | `8.6855399630e-03` | `8.6864646248e-03` | `1.065e-04` | 是 |

漂移随步数单调上升（`1e-7 → 4e-6 → 1e-4`），而**步数完全相同**——所以漂移不是时间推进
逻辑的差异，而是归约顺序/向量宽度在波陡化场中的放大。

### 3.3 线程假设：证伪

| 腿 | 1 线程 | 8 线程 | 场 sha256 | 逐位相同 |
|---|---|---|---|---|
| `p3.N100` | `1.58470068577237638e-02` | `1.58470068577237638e-02` | `4a8cdd3a…` / `4a8cdd3a…` | **是** |
| `p3.N200` | `1.21474701154990396e-02` | `1.21474701154990396e-02` | `80554edb…` / `80554edb…` | **是** |
| `p3.N400` | `8.68646462484351164e-03` | `8.68646462484351164e-03` | `cc57ab15…` / `cc57ab15…` | **是** |

`torch.set_num_threads(1)` 与 `(8)` 在三条腿上都给出**逐位相同**的密度场。
上游审计把「2 线程 vs 8 线程」当成成因，实际上它比的是「本机 vs 节点」——
**线程数不是成因，栈才是**（`torch 2.7.1` vs `2.13.0`、`numpy 2.4.6` vs `2.0.1`）。

### 3.4 台账度量在跨栈下是稳的

| 度量（`p3.N400`） | 已提交 | 本机重跑 | 相对漂移 | 是否 < 1e-6 |
|---|---|---|---|---|
| 全场相对 **L2** 密度（**台账臂**） | `3.1155618811580767e-02` | `3.11556198534853612e-02` | `3.34e-08` | **是** |
| 全场相对 **L1** 密度（现有 `reuse_check` 用的） | `8.6855399630e-03` | `8.6864646248e-03` | `1.065e-04` | **否**（超 106×） |

即：**验收读数（L2）换栈只动 3e-8，而 L1 的 1e-6 闸门在 `N ≥ 200` 上必然误报**。

## ⑤ 注意点

1. **闸门归属错位**：`test_shared_legs_agree_with_the_committed_pool`（`REUSE_TOL=1e-6`，
   比较 L1）只能证明「两个文件出自同一次栈」，不能证明「新机器能复现」。
   本单保留该闸门（它对**陈旧**仍然有效），并在新测试里显式登记它**跨栈会误报**
   （`test_existing_reuse_tolerance_is_stack_fragile`），使这条局限变成可执行断言而不是脚注。
2. **`lax_case_pool` 工件 `environment = null`**：provenance 缺口（工件早于记录器）。
   本单只把记录路径接进新模块与新基准，**没有**给历史工件补盖伪造的指纹；
   重生成池子工件（约 5–8 min）可补齐，未做，列为后续项。
3. **同栈逐位复现是本单能给出的最强承诺**：`test_same_stack_rerun_is_bit_identical`
   在本机重跑 `p3.N100`（17 s）并要求 `l1_density` **完全相等**（不是 1e-9 近似）。
   换机器时该测试按栈标签 skip，而不是放松容差。
4. **集群对照腿在飞**：`cj3284`（8 核，节点栈 `torch 2.13.0`）重跑同三条腿×两线程，
   为「同一栈上 artifact 是否逐位复现」提供对照。递交时仍在排队；工件按
   `(leg, threads, stack)` 三元组合并，作业落地后自动并入同一 `metrics.json`，无需改写测试。
   本报告中的所有数字均来自**已落盘**的本机栈行。
5. **不改验收**：台账臂 `p3.N400` rel L2 = 3.116 % 仍是 FAIL；本单只改变「这个数字有多可信」。

## ⑥ 误差判定（是否 < 3 %）

| 关键量 | 基准 | 数值 | 相对差 | < 3 % ? |
|---|---|---|---|---|
| `p3.N400` 全场 rel L2 密度（台账验收） | 精确 Riemann 解 | `3.11556e-02` | `3.116 %` | **否**（FAIL 原样保留） |
| 台账读数的跨栈可复现性 | 已提交工件 | `3.11556198e-02` vs `3.11556188e-02` | `3.34e-08` | 是 |
| `p3.N400` L1 的跨栈漂移 | 已提交工件 | `8.68646e-03` vs `8.68554e-03` | `1.065e-04` | 是（但 > 闸门 1e-6） |
| 线程数导致的场差异（1 vs 8 线程） | 同栈重跑 | 逐位相同 | `0.0` | 是 |

**结论**：本单量化的是**可复现性**（最大漂移 `1.065e-04`，全部 < 3 %），
**台账验收仍是 FAIL**（`3.116 %` > 3 %），未被本单改动，也没有被重新解释。
