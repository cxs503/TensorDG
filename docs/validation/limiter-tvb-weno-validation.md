# TVB / WENO limiter validation (TensorDG)

> Mission: **m2276** (self-start, data seat) · repository: `TensorDG` · branch `agent/m2276`
> Scope: verification debt of the shock limiters added in m274
> (`tensordg/limiters.py`, dev report `dev_report_tensordg-tvb-weno-limiter.md`).
> Grid used for the PDE block: 100 cells, P2, CFL 0.3.
> All numbers below are generated by `benchmarks/report_limiter_validation.py` from
> `artifacts/limiter_validation/*.json` — no value is transcribed by hand.

## 1. What was verified and why

The m274 development report accepted the limiters as *functional but not
production ready* and left two open items: (i) the limiter **increases** the
shock-tube error, (ii) the fix was announced as "problem-specific tuning of
`M`".  Neither claim had been checked against an analytic reference, so this
mission rebuilt the verification from scratch:

1. **Modal scaling.** For the normalised Legendre basis on ``[-1, 1]`` used by
   `euler_dg_1d._operators`, mode-0 is the cell average and mode-1 equals
   ``(dx/2) * du/dx``.  A minmod limiter must therefore write
   ``a1 = (dx/2) * minmod(d_left, d_right)/dx = 0.5 * minmod(d_left, d_right)``.
2. **Monotonicity preservation** (LeVeque 2002, ch. 6): for a monotone
   cell-average sequence the limited linear polynomial must stay strictly
   inside the neighbouring averages, i.e. the normalised slack must be > 0.
3. **TVB criterion** (Cockburn & Shu 1989): with tolerance ``M * dx^2`` a smooth
   extremum with ``|u''| ~ O(1)`` must stop being flagged once ``M > |u''|``.
4. **Shock-tube accuracy** against the in-repo exact Riemann solver
   (Sod 1978, Lax 1954) and a sweep of the TVB constant, which is the item the
   m274 report told the next agent to tune.

## 2. Defect found and fixed

`apply_tvb_limiter` assigned the bare minmod **difference of cell averages** to
the mode-1 coefficient, i.e. it used ``dx * du/dx`` where the basis requires
``(dx/2) * du/dx``: the reconstructed slope was exactly **twice** the intended
one.  The WENO branch was already written with the correct ``dx/2`` factor, so
the two limiters were mutually inconsistent.  One-line fix in
`tensordg/limiters.py` (plus a derivation comment), no API change.

Consequence, measured: the limited reconstruction sat exactly *on* the
neighbouring cell average (slack = 0 in every troubled cell) and the slope
error did not converge under refinement (observed order 0), because the 100 %
offset is independent of `dx`.

## 3. Analytic diagnostics, before vs after the fix

`observed order` = order of the limited-slope error under 4x refinement (20 -> 160
cells); `mean err n40/n160` = mean relative deviation of the limited mode-1
coefficient from the analytic ``(dx/2) du/dx`` in troubled cells of a smooth
concave quadratic; `slack` = worst normalised interface slack on a monotone
sigmoid (0 means the reconstruction touches a neighbour average);
`touch` = number of troubled cells with zero slack.

| variant | observed order | mean err n40 [%] | mean err n160 [%] | min slack | # cells touching neighbour avg |
|---|---|---|---|---|---|
| dispatch (published) | 0.00 | 76.9 | 91.6 | 0.000 | 19 |
| half-dx (fixed) | 0.00 | 20.8 | 6.5 | 0.189 | 0 |

Interpretation: the fixed limiter recovers a consistent, first-order accurate
minmod slope (error halves as ``dx`` halves) and preserves strict monotonicity;
the published one was off by a factor two and saturated the interface.

### TVB detector on a smooth extremum (`1 + 0.5 sin(2 pi x)`)

Number of flagged cells versus the client-supplied TVB constant `M`
(threshold ``M dx^2``):

| cells | M = 0 | M = 1 | M = 10 | M = 100 | M = 1000 |
|---|---|---|---|---|---|
| n40 | 19 | 19 | 19 | 9 | 0 |
| n160 | 79 | 79 | 79 | 69 | 0 |

The Cockburn-Shu scaling is confirmed: the extremum of this wave has
``|u''| = 2 pi^2 ~ 19.7``, and the detector
releases it once ``M`` exceeds that scale.  Note that with the strict TVD value
``M = 0`` the smooth extremum is clipped -- expected behaviour, but it is why
the default ``tvb_constant=1.0`` over-limits smooth waves.

The error is **flat** over ``M = 0 .. 100`` while limiter activity drops from
about a half to a fifth of the cells per sub-step; only ``M = 1000`` (which
switches the detector off almost everywhere) moves the error back towards the
un-limited run.  Conclusion: the accuracy regression of the limiters on Sod/Lax
is *caused by the amount of limiting*, not by the value of `M`, so the
"problem-specific tuning" recommendation of m274 is refuted by data.  The m274
advice that remains valid is the operational one: use the positivity-filtered
baseline when the target is pointwise accuracy, and the limiter only when
boundedness / TV control is the requirement (where it now behaves as designed).

## 7. Error verdict (3 % criterion)

| quantity | reference | error | < 3 %? |
|---|---|---|---|
| Sod density L2, no limiter | exact Riemann | 1.002 % | yes |
| Sod density L2, TVB (fixed, M=1) | exact Riemann | 2.377 % | yes |
| Sod pressure L2, TVB (fixed, M=1) | exact Riemann | 2.156 % | yes |
| Sod velocity L2, TVB (fixed, M=1) | exact Riemann | 6.916 % | no |
| Lax density L2, TVB (fixed, M=1) | exact Riemann | 11.834 % | no |
| limited mode-1 vs analytic `(dx/2) du/dx` (n=160) | analytic | 6.46 % mean / 100.0 % max* | mean yes, max no |
| interface monopoly (slack) | analytic | > 0 in every troubled cell | yes |
| exact half-dx scaling | analytic | < 1e-14 | yes |

\* the max is attained in the cell whose analytic slope vanishes (the smooth
extremum), where minmod returns zero by construction.

The velocity and Lax figures were already above 3 % in the published baseline
solver (`limiter=None`), so they are a *pre-existing* accuracy debt of the
scheme, not something this fix introduced.

## 8. Limitations / applicability

* Boundary cells are never limited (`troubled[0] = troubled[-1] = False`) while
  the flux assembly in `euler_dg_1d._rhs` is periodic (`torch.roll`); a shock
  sitting on ``x = 0 / 1`` is therefore unlimited.  Sod/Lax are flat there, so
  the numbers above are unaffected, but a periodic advection test would be.
* The detector takes ``max`` over the three conserved variables, so one
  non-monotone variable limits all of them.
* 1-D Cartesian meshes only; the WENO reconstruction is the simplified
  three-stencil slope version, not a full Qiu-Shu quadrature-node WENO.
* Reference data are exact Riemann solutions, not experimental data; the
  conclusion about limiter activity is grid dependent (100 cells, P2).
